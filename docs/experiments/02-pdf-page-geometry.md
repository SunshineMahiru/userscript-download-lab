# 实验二：PDF 页面尺寸与取向的归一

## 问题

幻灯片原始图片尺寸不一致：横版演示图常见 16:9，竖版文档截图可能是 1:2。若直接按像素当磅值写进 PDF，同一份文件里会出现宽度不一的页面，阅读器里翻页时版面跳动；若强行统一成 A4，横版内容会被压出大片空白。

需要确定一条归一规则，使页面宽度一致、比例保持、取向正确。

## 方法

固定页面宽度为 960 pt，高度按原图比例换算：

```
height = round(960 × 原图高 / 原图宽)
```

取向由换算后的高度决定：高度不小于宽度记为纵向（portrait），否则横向（landscape）。

写入时逐页调用 `addPage([宽, 高], 取向)`，第一页用构造参数给出，后续页显式切换。

## 复跑命令

```bash
node tests/slides.test.mjs
```

用例用两张固定图片（160×120 的横版、100×200 的竖版）生成三页 PDF，再从字节流里读回 `/MediaBox` 校验。

## 数据

| 原图尺寸 | 换算后页面 | 取向 |
| --- | --- | --- |
| 160 × 120 | 960 × 720 | 横向 |
| 100 × 200 | 960 × 1920 | 纵向 |
| 160 × 120 | 960 × 720 | 横向 |

从产物字节流里读回的实际值：

```
/MediaBox [0 0 960 720]
/MediaBox [0 0 960 1920]
/MediaBox [0 0 960 720]
```

页对象数量为 3，文件头为 `%PDF-`，体积 13 KB 量级。

## 结论

固定宽度、按比例换算高度，可以让同一份 PDF 的页面宽度一致，同时保留原始比例。取向按换算后的高宽比较判断，横竖混排的文件不会出现内容旋转。

三种规则被否掉：

- **按像素当磅值**：160 px 的图变成 160 pt 宽，页面过窄，打印时字迹过小。
- **统一 A4**：横版内容上下留白超过一半，等于放弃了版面。
- **统一正方形**：所有比例都被拉伸或留边，混排版面最难看。

## 局限

960 pt 这个宽度是经验值，没有针对具体阅读设备做优化。若目标是在平板上全屏阅读，宽度取屏幕宽度的磅值等价量会更合适。

图片重编码为 JPEG（质量 0.92）后写入，文字类幻灯片会在大面积纯色区域出现轻微噪点，矢量图转位图后也无法再放大。这是把图片序列合成 PDF 的固有代价，不是本实现的选择。
