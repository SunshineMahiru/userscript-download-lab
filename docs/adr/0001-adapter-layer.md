# ADR-0001 适配器只描述，不执行

- 状态：已采纳
- 日期：2026-11-09
- 影响范围：引擎与站点的全部边界

## 背景

项目要覆盖多个站点的差异，同时仓库不能包含任何真实站点的实现。

若适配器被允许自行发请求、写页面、决定下载方式，站点知识就会从适配器渗进调度逻辑：每加一个站点，调度层都要跟着改；每一类错误的处理要写好几遍；测试也不得不联网或伪造响应才能跑起来。

## 决策

适配器是一组纯函数。它读上下文、拼地址、解析响应，产出数据结构，然后返回。它不发起请求，不写 DOM，不决定下载方式。

引擎负责调度请求、归一错误、执行下载、更新界面。

仓库只注册一个针对合成站点的参考适配器。真实站点的适配器由使用者自行注册，引擎因此必须容忍零命中：没有适配器匹配当前地址时，界面提示不可用，不抛错。

## 后果

正面：

- 换站点不需要改引擎，判断标准只有一条——这行代码是否知道某个具体站点的存在。
- 适配器可以脱离网络做单元测试，输入是固定的上下文与响应。
- 仓库可以公开，因为里面没有任何真实站点的名称、域名与字段。

负面：

- 接口函数增加到八个，理解成本高于「一个方法搞定」的形态。
- 某些站点特有的请求流程，例如多次跳转或动态签名参数，需要塞进 `RequestSpec` 或要求引擎扩展能力，接口有被动扩张的压力。
- 引擎与适配器之间多了一层对象传递，调试时要多看一层。

## 被否选项

**让适配器直接返回最终地址并自行请求。** 这样接口最少，只有一个函数。否掉的理由有三条：测试必须联网或伪造响应；错误处理分散在每个适配器里，同一类错误要写多遍；站点特有的重试与请求头逻辑无法被统一约束。
