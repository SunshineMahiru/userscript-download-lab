# ADR-0002 传输层注入，测试不伪造行为

- 状态：已采纳
- 日期：2026-11-09
- 影响范围：请求层、下载层、全部端到端测试

## 背景

引擎通过脚本管理器提供的全局函数发请求与执行下载。测试环境没有这些全局函数，也没有浏览器下载管理器。

如果测试里放一个假对象顶替它们，被验证的只有「函数被调用了」，而不是「请求发出后发生了什么」。错误码映射、重定向跟随、响应类型判定这些真正容易出错的地方，全部被假对象挡住，等于没测。

项目规则明确禁止用伪造对象来让测试通过。

## 决策

引擎对外暴露一个传输参数：`createEngine({ transport })`。

生产环境传入基于脚本管理器接口的实现，测试传入基于 `node:http` 的实现。

传输层只替换「怎么发」，不替换「发出去得到什么」。测试的响应来自真实运行的本地服务器，服务器返回真实的状态码、真实的跳转、真实的签名过期。

## 后果

正面：

- 错误码、302 跟随、签名过期、响应类型判定都在真实链路上跑过。
- 测试不需要联网，服务器与用例在同一进程内启动。
- 传输层的两个实现共用同一份接口，生产环境的差异被压缩到一个文件里。

负面：

- 引擎的构造签名多一个参数，入口处必须显式装配，漏传会直接报错。
- 端到端测试依赖服务器先启动，用例之间存在启动顺序的耦合，端口冲突会让整组失败。
- 传输层成为引擎的一部分接口，改动它要同时改两个实现。

## 被否选项

**在测试里替换全局的请求与下载函数。** 这样测试代码最短，也不必启动服务器。否掉的理由是它把被测行为挡在了替身之后：错误归一没有被执行过，重定向没有被执行过，最后得到的是一份「调用次数断言」，而不是行为断言。
