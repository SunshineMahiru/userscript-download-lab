# 手工验收清单

自动化能证明产物可以执行、能挂载面板、能经管理器接口走完下载链路，但证明不了「在真实脚本管理器里装上去能用」。下面这几步只能在浏览器里做，做完把结果填进最后那张表。

## 前置

- 一个支持 `GM_xmlhttpRequest` 与 `GM_download` 的脚本管理器：Tampermonkey、ScriptCat、Violentmonkey 任一。
- Node 20 以上，仓库已克隆并执行过 `npm ci`。

## 步骤

1. 起合成站点：

   ```bash
   npm run serve
   ```

   终端应打印 `合成站点已启动：http://127.0.0.1:8080/`。浏览器打开该地址，应看到三个链接。

2. 安装脚本：管理器里新建脚本，把仓库根目录的 `userscript-download-lab.user.js` 全文粘进去保存。管理器应显示脚本已启用，匹配范围是 `http://127.0.0.1/*`——不带端口，换端口才不用改脚本。

3. 打开 `http://127.0.0.1:8080/chapter/ch-1`。页面左侧应出现竖排的「实验面板」书签，浏览器控制台无报错。

4. 点击书签展开面板，点「解析本章资源」。列表应出现 5 项，状态行显示「已解析 5 项资源。」，底部按钮变为「下载选中（5）」。

5. 取消勾选任意一项，按钮应变为「下载选中（4）」，列表计数仍为「5 项」。

6. 取消勾选「过期资料.pdf」，点「下载选中（4）」。期望 3 个文件保存成功，`课堂录像（分片）.m3u8` 失败——Tampermonkey 把播放列表当媒体流处理，会去解析里面的分片地址，报 `not_whitelisted`。这条不是配置问题，是清单文件本就不能当单文件下载。

7. 重新勾选全部五项再下载一次。期望「2 项失败，首个原因：not_whitelisted …」，另一个失败是 `过期资料.pdf` 的 `http-403`。其余三条仍完成——单条失败不中断整批。

8. 把书签拖到页面下方，刷新页面。书签应停在拖动后的位置附近（吸附误差不超过 16 像素）。

9. 在开发者工具的「应用 → 本地存储」里删掉 `udl-tab-ratio-v1`，刷新。书签应回到垂直居中的默认位置且不报错。

10. 打开 `http://127.0.0.1:8080/`。点解析应提示「当前页面不是章节页」，而不是静默无反应。

11. 打开 `http://127.0.0.1:8080/slides-viewer`。面板一挂载就该提示「已找到幻灯片序列，至少 6 页」——这句来自挂载时的探测，不应该点过「合成」才出现。点「合成幻灯片 PDF」，状态行依次显示统计页数、逐页合成、写入 PDF，最后提示已保存。浏览器应下载一个 6 页的 PDF，页面为 339 × 190 毫米（960 × 540 pt），比例 16:9。

## 已知未覆盖

- 跨域 iframe 内的资源不在覆盖范围：当前实现只在顶层文档运行，不进子框架。
- 签名过期与签名篡改这两条只在自动化里验证过。手工走一遍需要等 5 分钟让签名过期，或用开发者工具改写 `Location` 里的 `exp`，不在清单内。
- 无痕窗口下的存储拒绝没有单独列步：Chrome 无痕里 `localStorage` 仍可用，测不到拒绝路径。第 9 步验的是「键不存在时用默认值」，两者相邻但不是同一件事。

## 真机踩过的坑

这三条在自动化测试里复现不了，都是装进管理器后才暴露的：

1. **`GM_*` 不在 `window` 也不在 `globalThis` 上**。Tampermonkey 在 `@grant` 模式下把它们注入脚本作用域，只有直接引用标识符才取得到。按对象属性取会在构造传输层时就抛错，面板根本挂不上。
2. **`GM_download` 受 `@connect` 约束，`GM_xmlhttpRequest` 同源豁免**。缺 `@connect 127.0.0.1` 时解析一切正常、下载全部失败，两边的表现差得很远。
3. **下载撞上 4xx 时管理器给的是状态短语而不是内部码**。Tampermonkey 返回 `Forbidden`，不归一成传输码就只剩一句无用的兜底提示。
